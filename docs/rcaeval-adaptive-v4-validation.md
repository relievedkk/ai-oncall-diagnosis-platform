# RCAEval adaptive v4：完整性与安全验证

> 历史归档：2026-11-04 已删除 V4 运行入口及专用协调器/补查实现。下列 V4 命令不可再执行。当前方案见 [V5.1 全量评测](rcaeval-v51-full-evaluation.md)，本页只保留历史测试与实验记录。

日期：2026-11-03。实现起点：`84ad887`。本轮实现用户批准的 P0–P2 修改，采用先诊断、按缺口补查的协议 v4。

## 实现内容

- 第一次调用直接生成诊断；经策略校验的完整结果立即结束。证据不足时，由确定性规划器生成最多一次补查，模型最多调用两次。
- 已授权的候选/hint、服务绑定引用、机理、视图与原始请求仍严格校验。允许未知根因时扩展至多一个带独立依据的 hint。
- RCAEval 专用输出枚举覆盖 cpu、mem、delay、disk、loss、socket、unknown；根因、假设与候选比较使用相同词汇。通用生产报告保持兼容。
- 路由、诊断提示分开，去除旧工具工作流冲突。新记录显式保存 prompt/evidence revision，禁止混合协议或 revision 汇总。
- 结构解析失败保留 provider usage，并保存固定问题码与白名单字段路径；不保存原始响应、输入值、秘密字段名或异常全文。
- 部分遥测保留有限观测和采样数量；缺基线、缺故障后数据、非有限值及来源不可用分别表达。缺少整个日志文件、空日志、缺 trace 均不会使指标诊断直接崩溃。
- 趋势按请求机理过滤。补查增加稳定的时间细节引用，使用持续变化、采样间隔、起始时间区间比较竞争机理；公共噪声、缺少竞争者、重叠时间区间保留歧义。
- 只有可信验证器独立读取原始遥测并复算整个补查包，才可授权消除歧义。确认新机理时同步撤销旧竞争机理的原因资格；旧观测仍可用于比较。
- 补查、验证、模型及策略共享累计期限。第二轮失败保留已验证首轮结果，保存增强失败、调用次数、补查哈希与结果选择原因。
- 补查增量按观测内容计算，子集、重排、换引用名不构成新证据。没有新信息时跳过第二次调用。
- 输出目录必须为空。开发集审计要求显式 DevelopmentScope，绑定已使用的 18 例 ID 和批准的答案文件；在任何遥测/答案访问前拒绝封存样本或不匹配来源。
- 每个 v4 结果包含独立于模型文本的 `evidence_coverage`：逐候选、逐机理报告状态、比较数据是否可用、诊断资格及部分数据采样数量。

## 测试覆盖矩阵

| 范围 | 验证方式 |
| --- | --- |
| 六类故障与 unknown | 枚举边界测试；六类合成遥测经过真实提取器/策略/配对流程 |
| 缺字段、额外字段、非法机理 | 类型拒绝、固定错误类别与安全问题码；引用/字段值不泄露 |
| provider 用量与失败 | 解析失败仍保留实际 usage，首轮失败无伪造回退 |
| 数据质量 | 缺基线、缺后段、零基线、常量、NaN/Inf、空/缺日志、缺 trace |
| 授权与身份 | 越权服务/hint、请求不匹配、重复/真实冲突引用；现有 v3 回归保留 |
| 补查有效性 | 恢复被省略详情、时间证据新增；已有观测子集/换名不得触发第二轮 |
| 机理区分 | 分离/重叠/相同起始区间、短暂先发信号、竞争者缺数据、公共噪声、伪造包 |
| 超时与取消 | loader、policy、两次模型共享预算、第二轮结束后的临界期限、验证阶段取消 |
| 结果完整性 | 完整首轮一次结束、第二轮失败保留首轮、部分结果选择、精确调用数与哈希 |
| 评估边界 | 相同初始哈希、两边冻结后加载真值、分层/配对增减、版本隔离、非覆盖写入 |
| 盲测隔离 | 54 例仅检查遥测；开发审计只允许显式批准的已使用 18 例 |

合成固定模型输出测试验证系统链路，不测量模型推理准确率。数据库/Docker 等集成测试依赖单独环境，跳过项不视为已验证。

## 运行方式

先执行零模型验证与已使用开发集的证据覆盖审计，使用全新输出目录：

```powershell
.\.venv\Scripts\python.exe -m app.evaluation.rcaeval --mode validate --protocol-version 4 --data-dir .runtime\rcaeval\heldout-54-v1\tasks --output-dir .runtime\rcaeval\v4-validation-new --audit-development
```

付费模型验证是独立实验，以下命令只作用于已使用的 18 例，输出目录也必须全新：

```powershell
.\.venv\Scripts\python.exe -m app.evaluation.rcaeval --mode live --allow-live --protocol-version 4 --data-dir .runtime\rcaeval\heldout-18-v1\tasks --answers-file .runtime\rcaeval\heldout-18-v1-sealed\answers.parquet --output-dir .runtime\rcaeval\v4-live-new --max-calls 2 --timeout-seconds 180
```

每种策略每例最多两次实际调用。`--protocol-version 3` 保留旧协议执行入口；修订后的提示和证据也会记录 revision，历史产物保持原样。

## 能力边界

测试覆盖不等于 100% 根因准确率。缺少网络丢包证据、没有故障前基线、多个信号无法区分时，正确行为是明确报告缺口或 unknown。时间先后与异常强度均为辅助判断，不能单独证明因果关系。

开发集证据资格审计给出的是当前规则允许的答案范围；判断 Agent 是否优于基线，还需要新协议实跑的配对增益、丢失命中、错误率、拒答率和成本。剩余 36 例应在实现冻结后才进行最终盲测。
