## CPU 采集语义核查

原始3例均有持续 CPU 上升，正确 CPU 候选已经进入 Top5。指标单位与类型为 unknown 是原资格检查的唯一缺口。官方论文第3.2节将 CPU 故障的指标明确为容器 CPU 使用量；公开读取代码没有提供对应 CPU 查询式、物理单位或 CPU quota 分母。因此本轮只增加有来源的 `quantity=cpu_usage` 和 `relative_change_only`，保留 `unit=unknown`、`metric_kind=unknown`，不计算 CPU 饱和度或百分比。

这个档案只适用于已明确标识的 RCAEval RE2 输入；普通输入不自动套用。`*_cpu_seconds_total` 等其他名称不会继承该语义；counter 仍须显式声明。负载增长、重试/GC、资源共变和独立响应对照仍参与资格检查。新增测试同时修复了 unknown counter 单位派生为 `unknown/second` 后被误当成已知单位的漏洞。

| 开发案例 | 原资格 | 接入已核实的指标含义后 | 单位 |
| --- | --- | --- | --- |
| case-013 | 不满足 | 满足当前对照规则 | unknown |
| case-022 | 不满足 | 满足当前对照规则 | unknown |
| case-054 | 不满足 | 满足当前对照规则 | unknown |

这是程序证据资格的变化，真实模型准确率尚未测量，仍需逐例核对因果判断。

默认 v5 CLI 对明确清单声明的 RCAEval RE2 使用 `--telemetry-profile rcaeval-re2`；没有清单或其他来源使用 `--telemetry-profile unknown`，不能继承旧读取器的默认名称冒充来源。档案传入基础、全部时间扰动、validate 和 live 证据路径，并进入包体/配置指纹。

## 18 例归因与候选修复

归因报告独立列出来源语义、正常期覆盖、候选选择、证据资格、包体与竞争解释；每例保留支持、反证、对照 refs。不存在“提取器没有某字段，因此原始数据肯定不存在”的自动结论。标签只在基础/消融/时间扰动特征及候选冻结之后进入审计。

修复采用统一规则，没有案例 ID 特判：

- 保留缺基线的后段观测，并标明缺口；它可进入候选，不能据此确诊。
- 对有持续性、起始区间且中位数至少上升25%的弱 socket 信号保留候选；仍需连接资源证据才能定型。CPU 使用量上升同时存在此类连接压力时保留竞争解释。
- 在资源/负载对照下无法区分网络延迟与丢包时，为选中的端点保留两个解释，占用同一个最多5项预算，不给予 loss 诊断资格。
- 用同一资源族在多服务间的共变比例做检索对照，减少公共变化挤占候选。检索分数不作为概率或资格。

## 包体与单请求边界

协议版本为 `single-pass-v5.1-20261103`。使用位置表、字段图例、服务前缀和重复 JSON 值/结构共享，保留浮点精度、null/缺字段区别及全部材料引用。普通显示摘要可省略；关键支持、反证与对照不删除。

原始数据里的 `$v`、`$literal` 等同形标记包进不透明 literal 块，模型和本地消费者均不能递归解释其中内容。新增独立协议消费者回归，复现并修正了仅本地复制能还原、模型却会误解为自引用的问题。

两个原始大包回归还检查了真实 SDK 请求包络及输出预留。单次请求持久化占用、重启后不重发、超时/取消/解析错误及 usage 保留均继续通过模拟验证。
