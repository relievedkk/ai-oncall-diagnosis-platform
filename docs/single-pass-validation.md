# 单阶段诊断 v5：实现与验证

日期：2026-11-03。范围：本地 RCAEval 评测链路。既有在线诊断 API 未迁移到这条实验链路。

## 已实施的流程

指标、日志和 Trace 在本地统一提取，生成最多 5 个服务＋机理假设；一次结构化模型请求后，程序独立校验引用与证据权限，再用本地模板出报告。候选分数不代表概率，不能直接确诊。

- 固定事件前后 300 秒，裁到记录边界；对开发集额外做 ±30/60 秒扰动和 metrics / metrics+logs / 全源消融，均不调用模型。
- 指标保存正常期与故障期覆盖、持续变化、起始区间、多尺度及形态；unknown 单位保持 unknown，counter 必须显式声明。缺失不当作零，极端有限浮点不生成 Inf。
- 日志按服务、事件和时间桶聚合。相同打印不算独立支持；所有已识别事件先聚合，之后才限制普通模板。原文脱敏且不可信，注入控制描述不进入证据。
- Trace 仅在同一 trace 中关联父子；并行子区间取并集。重复、循环、孤儿、截断和时间关系不完整时降低证据等级，不伪造父节点自身耗时。未知状态码不当作成功。
- 每个假设保留支持、反证、对照、竞争解释及缺口。明确竞争事件未解决时不确诊。类型 unknown 时可以保留有独立支持的服务。
- 证据包绑定 case/window/ref，使用短别名；包括转义、schema、提示词和输出预留的预算不超过 16 KiB。关键材料装不下时零调用失败，不静默删除反证。

## 一次请求的持久化约束

SQLite `.runtime/rcaeval/single-pass-attempts.sqlite` 以 experiment_id＋case_id 唯一占用。packet、模型配置、schema、提示词和代码版本共同形成指纹，在发送前写入。不要删除该数据库或为重试更换实验 ID。

成功结果只有 `--resume` 才复用；配置变化拒绝复用；重启后 reserved、超时、取消、解析失败及不明响应均不会自动重发。SDK retries=0，无格式修复、第二轮诊断或模型摘要。解析失败仍保存已观察用量，未知用量明确标记。调用数是已占用尝试数；恢复时不把历史消耗计为零。

真实 SDK 的 Mock HTTP 测试覆盖有效响应、损坏 JSON 和 HTTP 500，检查三者每例均只有一个 HTTP 请求；不访问供应商，不产生费用。

## 本地运行

在项目目录使用原有虚拟环境（需已安装 pandas/Parquet 评测依赖）：

```powershell
.\.venv\Scripts\python.exe -m app.evaluation.rcaeval --mode validate --audit-development --output-dir .runtime/rcaeval/my-single-pass-audit
```

默认协议已切换 v5，默认模式仍为 validate。显式 `--protocol-version 3` 或 `4` 保留历史路径；v5 的 `--max-calls` 只接受 1。输出目录须为空，避免覆盖。全源库存和逐例缺口在生成的 `development-audit.json` 内。

付费路径仅允许既有 18 例开发目录；必须 18/18 审计完成、至少 17/18 正确联合假设进入 Top5、至少 17/18 获得可区分证据权限、18/18 包体通过且无审计错误。还需人工核对审计并提供匹配的 reviewed audit SHA、实验 ID 与 allow-live。自动资格检查不是因果证明，不能替代人工逐例审阅。门槛未满足时停止付费。

剩余 36 例答案不在本次可访问的审计范围；v5 付费入口也不开放该盲测。后续独立测试须另行授权、先冻结预测再开答案。

## 解释结果时的限制

这次实现不承诺 90%，不把候选召回当成模型命中率。18 例达 90% 需要 17/18，独立 36 例需要 33/36；小样本不代表业务准确率。总 tokens 约 5,000/例是待实测目标，16 KiB 是字节边界，两者不能换算等同。本次不运行付费模型，不能声称已降低真实 token 成本或提高模型准确率。

验证结果及剩余缺口见本文后续的实测记录。
