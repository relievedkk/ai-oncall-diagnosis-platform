# Windows 本机运行保障设计

日期：2026-10-24。状态：用户已批准；在当前目录实施，保留现有前端修改。

## 目标与约束

用户要求补齐进程守护、独立监测、备份恢复演练、积压告警、共享额度、发布回滚和任务重连，已明确选择“主要完善 Windows 本机的部署与演练”。

沿用 Windows 原生 API/MCP、Docker Desktop 内的 PostgreSQL/RabbitMQ/Milvus/Worker，保留现有认证、任务所有权、处置 Dry Run 和已有前端修改。交付可运行的程序、PowerShell 入口、测试、演练命令及结果记录。不能把同机探针称为异机容灾，也不能把配置存在称为演练通过。

本次不建设 Kubernetes、数据库高可用、多租户权限或真实基础设施写适配器，不发送实际通知、不调用付费模型进行演练。单机停机维护是本次可接受的运维方式；备份窗口与发布窗口必须在操作前显示。

## 方案选择

1. **现有混合架构加固（本设计采用）**：以独立运维程序与 PowerShell 脚本管理原生进程及现有 Compose。用户选择的 Windows 本机方向与现有运行结构一致，避免为守护和演练迁移整个运行栈。
2. **全部迁移至 Docker Desktop**：统一进程管理，但要迁移 CLS 的 Node 子进程、API 上传目录、网络与发布方式；本次不采用。
3. **Windows 服务第三方包装器**：需要额外安装和管理员环境；本次以用户级计划任务作为可选登录启动入口，不引入第三方常驻软件。

用户已在本设计交付后回复“好的”，批准上述 Windows 方案及在当前目录实施。

## 一、进程守护与维护模式

- 增加独立于 `app` 包初始化的运维入口，PowerShell 负责调用，业务进程仍使用项目自己的 Python 环境。
- 守护器启动 API、CLS 网关和 Monitor MCP，保存本次运行 ID、直接持有的进程句柄、命令路径和日志位置；互斥锁防止同一工作区重复启动。
- 子进程隐藏启动，标准输出和错误写入独立日志。只操作由本守护器创建且身份匹配的进程，不按端口或窗口标题杀进程。
- 子进程退出后退避重启：1、2、4、8、16、30 秒，上限 30 秒；每个服务每 5 分钟最多重启 5 次，超限进入可见的 degraded 状态。
- API 通过 `/live` 检测事件循环卡死，连续三次失败才重启；`/ready` 失败仅报告依赖降级，不重启数据库故障下的健康 API。MCP 首期以进程存活及有界协议探测为准，不向真实云端发查询。
- 新增受限的维护状态和排空流程：关闭新聊天、手动诊断、Webhook 入队和知识写入，等待已接纳 HTTP 写入/聊天结束以及持久诊断/处置任务结束；超时退出维护操作并报告，不强制进入备份。
- API 提供仅供本机运维控制、带独立凭据的排空/关闭机制，或等效的仅工作区所有者可写的控制通道；不得开放无认证的远程停止接口。具体机制由实施者在计划中固定。
- 停止守护器先写停止意图，阻止自动拉起，再有界关闭自己拥有的进程。可选计划任务仅在用户显式执行安装命令后注册，登录启动而不是宣称开机前服务可用。
- Docker 长期服务补 restart 策略；迁移和队列初始化仍为一次性任务。Docker Desktop 未运行时明确失败，不能返回“全部启动成功”。

验收：终止守护器拥有的测试子进程可自动恢复；重复启动被拒绝；依赖探针失败不形成重启风暴；维护超时、外来占用端口和停止期间崩溃均有行为测试。

## 二、独立监测

- 提供单独启动、具有独立配置和结果目录的 Windows 探针，可复制到另一台 Windows 机器。
- 对 API `/live`、带机器认证的 `/ready`、Prometheus 与 Alertmanager 就绪端点做有界检查；凭据从环境/本地配置读取，不放进进程参数和输出。
- 连续失败三次记为故障，连续成功两次记为恢复；仅在状态变化时写事件，另写最后运行时间和原子状态文件，支持一次性模式及明确退出码。
- 通知先交付本地事件/JSON 和可配置告警接收配置。平台自身不可用告警必须可送往独立接收端，不能只回调平台。未配置外部接收端时明确提示未形成异机通知闭环，测试不发送真实消息。
- 探针以独立进程运行；同机模式不抵御宿主机断电、系统崩溃或 Docker Desktop 整体失效。

验收：测试 HTTP 服务关闭后探针产生故障，恢复后产生恢复，超时有界，不泄露凭据，不把 401 当健康；原始结果可用于面试演示。

## 三、备份与隔离恢复演练

- 采用有维护窗口的冷备份：先进入维护并排空，再停守护业务进程、Worker 与 Publisher，然后有序停止持久化依赖，确认无运行中的写入者后备份。
- 备份包含 PostgreSQL、RabbitMQ、Milvus、etcd、MinIO 的完整数据卷，以及 `uploads` 对象/清单、服务目录和当前应用发布标识。所有数据均停止后归档，避免把运行中的卷复制称为一致备份。
- 从有效 Compose/容器挂载信息解析卷，不依赖猜测的项目前缀；备份 manifest 记录组件镜像 ID、原 RabbitMQ hostname/nodename、卷映射、数据库版本、文件数量、SHA-256、开始结束时间及一致性方式，不保存密钥。
- `.env` 不进入普通归档。恢复时显式提供恢复环境凭据；备份目录限制为当前用户可访问，文档说明异地副本需加密存储。
- 归档写入临时目录，全部成功并校验后才原子发布 manifest；失败备份没有 success 标记。无论成功与否，finally 尝试恢复原来运行的服务，保留恢复失败的明确错误，不能以原始备份错误掩盖重启失败。
- 默认恢复目标只能是新建的隔离演练环境：随机容器、网络、卷和不冲突的本地端口，禁止引用源业务卷；保留原 RabbitMQ 节点身份以验证其持久数据，不启动会自动消费/执行的业务 Worker。
- 校验归档哈希及成员路径，拒绝绝对路径、父目录逃逸、链接逃逸和重复目标。写入前确认目标是本次演练创建且为空的资源。
- 恢复后检查数据库 Alembic 版本、任务/报告/检查点/知识版本记录，RabbitMQ 队列与消息摘要，Milvus 可用性与选定集合信息，上传文件清单哈希。向量样例查询用预先保存的合成向量，不调用外部 embedding。
- 演练入口默认创建合成业务数据的独立栈并执行备份→恢复→核对，输出各阶段耗时与结果；只有执行成功才记为恢复演练通过。记录实测 RTO 和快照时间，不承诺未经测量的 SLA/RPO。
- 不提供无保护覆盖当前生产卷的快捷命令；本次实现及验证不把恢复演练写入现有业务卷。

验收：合成任务、报告、上传文件、队列消息和合成向量恢复后可核对；损坏归档、缺失卷、目标非空和演练中断拒绝误写；正常备份后原服务可恢复。

## 四、积压与监测时效告警

- 保留已有死信、无消费者、Outbox 滞留告警，增加待处理队列深度与持久任务最老等待时长。
- 建议初值：critical ready > 10 持续 2 分钟；default ready > 50 持续 5 分钟；queued/retrying 最老等待 > 120 秒持续 2 分钟。阈值可在规则文件调整，文档明确它们是初始值而非容量结论。
- 增加采集最后成功时间；采集失败不得继续以旧值假装正常。使用 `absent`/采集时效规则覆盖指标消失。
- 运行保障自身告警标记为独立路由，避免队列积压告警继续自动创建诊断任务、加重积压。外部接收地址由部署者配置。

验收：使用 promtool 规则测试覆盖阈值、恢复、无数据和独立路由；使用假时钟/仓库测试最老等待时间和指标更新。

## 五、API 与 Worker 共享模型额度

- 复用 PostgreSQL，不新增 Redis。按供应商账户范围共享额度，不能按进程/模型分别计数而绕过同一账户限制；范围使用不含秘密的配置标识。
- 增加数据库迁移及仓库：调用前在事务内原子预留并发租约、分钟调用次数和分钟累计输入字节。默认建议为并发 4、每分钟 60 次、每分钟输入 1 MiB；配置范围、初值须写入示例配置。
- 并发租约有唯一调用 ID、数据库时间、过期与续约；模型调用期间续约，完成/异常释放，进程崩溃后到期回收；已经预留的分钟次数/字节不因调用失败退回，避免失败风暴重复占用供应商。
- 并发上限定义为数据库中有效调用租约数量，不承诺失联后供应商实际在途请求立即归零。租约续约失败后当前调用尽力取消，调用方不得继续发起新调用；回收期限至少覆盖配置的请求硬期限及安全余量。进程暂停、网络失联或供应商继续生成可能造成短暂的实际上游并发偏差，需在故障测试和文档中单列，不能以租约数冒充严格供应商并发。
- 对所有通过现有模型工厂的聊天、摘要、AIOps、结构化模型调用生效；保留已有单任务持久预算。embedding 不在本次 LLM 额度范围，明确单列。
- 供应商 429 的冷却时间写入共享状态，各进程共同遵守。数据库不可用时启用共享额度的调用拒绝执行，不退回本地无限制调用。
- 新的 Windows 托管部署配置启用共享额度，保留显式关闭项以兼容离线测试；提供启动检查防止只在 API 开启而 Worker 未开启。
- 额度耗尽返回可识别错误/Retry-After。后台诊断遵循现有重试策略和总预算，不能增加无界重试。调用/输入字节限额不宣称是精确 Token 或金额控制。

验收：两个独立仓库实例/数据库连接并发抢额度不超卖；进程重启不重置分钟预算；租约过期回收；迟到释放不影响新调用；取消、续约失败和 429 冷却均有测试。

## 六、Windows 发布与回滚

- 增加发布包：固定源代码快照与依赖锁、版本标识、SHA-256 manifest；排除 `.env`、运行数据、日志、缓存及虚拟环境。默认可从当前工作区打包，不能擅自丢弃现有未提交前端修改。
- 发布目录使用不可变版本目录，每版独立 Python 依赖环境，守护器从原子 active-release 指针读取目标；升级前验证依赖、配置和数据库 schema 兼容性。
- 固定绝对路径的共享 DATA_ROOT 与 CONFIG_ROOT，独立于各 release：uploads 对象/清单、运维状态/日志、备份目录与凭据留在共享根；静态资源、迁移文件和代码从所选发布目录读取。不得靠切换 cwd 让相对 `./uploads` 指向新版本空目录；显式配置路径和回归测试覆盖切换与回滚后读取同一份新增文档。
- API/MCP 与 Worker 镜像使用对应的不可变发布版本，避免 API 回滚但 Worker 仍运行新代码。发布记录保存前一版本、镜像 ID、schema 版本与配置摘要，不保存秘密。
- 发布流程：预检→维护排空→必要的兼容迁移→切换同版 API/MCP/Worker→`/live`、`/ready` 与无付费模型的业务冒烟→成功记录；失败时有界切回兼容的上一版并再次验证。
- 数据库迁移只允许显式声明向后兼容的升级。应用回滚不自动执行 Alembic downgrade，也不自动恢复旧数据库覆盖新数据；存在不兼容迁移时在发布前阻止“自动回滚”模式，要求先制定独立维护方案。
- 保留最近两版，清理只作用于受管理发布目录且当前/上一版本不可删；不自动切换当前开发目录的文件。

验收：合成新版本健康失败后切回上一版，指针与 Worker 镜像一致；包校验失败、路径逃逸、迁移不兼容时在切换前拒绝；演练报告标记未测试的真实部署条件。

## 七、持久任务重连

- 新增创建任务接口，先返回持久任务 ID，再按任务 ID 订阅 SSE；保留原 POST `/api/aiops` 的兼容行为。
- 创建接口支持客户端生成的幂等键，按当前认证主体限定范围，在数据库唯一约束下创建一次任务与 Outbox；相同键、不同请求拒绝。
- 新增 `/api/aiops/jobs/{diagnosis_id}/events`，支持 `Last-Event-ID` 或明确的 `after_id`，逐条使用持久 evidence ID，终态事件使用可稳定去重的 ID。仅重连绝不创建新任务。
- 订阅遵守当前可信单团队认证边界，手动新建任务同时记录创建主体，禁止另一主体借新订阅接口读取该手动任务；告警任务保持既有共享运维可见范围，历史任务兼容规则在计划中固定。
- 浏览器保存当前主体下的活动任务 ID、创建幂等键、最后已应用事件 ID及展示进度；连接中断指数退避自动重连，上限 30 秒，认证失效停止；刷新页面能恢复，身份切换清除旧状态并取消旧请求。
- 前端按事件 ID 去重，中文多字节跨块、SSE 注释/心跳、多行 data、截断帧和终态重放均正确处理；收到完整事件后才推进游标。
- 本次不新增取消任务语义；“断开订阅”和“后台任务停止”必须明确区分。

验收：模拟连接在事件中间断开，重新订阅得到余下内容且无重复；刷新恢复原任务；两次创建请求只产生一个任务/Outbox；完成后重连返回同一最终报告；账号切换不恢复旧任务。

## 交付拆分与验证

设计批准后写四组实施任务，分别覆盖：

1. Windows 守护、维护和独立探针。
2. 队列时效指标与告警、数据库共享模型额度。
3. 持久任务创建/事件协议与前端重连。
4. 一致备份、隔离恢复、版本发布与回滚，最后整体验证。

先补失败回归，再实现对应行为；保留现有前端改动。默认测试不访问付费模型或真实云日志。需显式启用的真实 PostgreSQL/Docker 集成只在随机隔离资源上运行；真实数据备份需先展示维护窗口，恢复验证始终写入新建隔离资源。

当前项目 Python 3.13 启动器曾异常，基础解释器执行受限；已只读确认工具自带 Python 3.12.14 能启动，尚未据此确认项目所有依赖可用。进入实施前先验证测试环境与基线。当前工具环境找不到 Docker 命令，常见 Docker Desktop 安装路径也不存在；真实卷备份/恢复及 Worker 镜像回滚演练以可访问的 Docker Desktop 为前置条件。可先完成程序、离线故障测试及配置，但无法运行的集成检查必须记录为未验证，不能用静态检查或历史通过数替代，也不能把缺少 Docker 的环境写成恢复演练通过。

## 已批准的关键取舍

- 保留 Windows 混合架构，以用户级守护与可选登录启动为目标。
- 使用维护窗口冷备，交付隔离恢复演练，避免在线跨系统快照一致性承诺。
- 共享额度复用 PostgreSQL；限制调用/字节和并发，暂不做精确计费及 embedding 全局限额。
- 发布使用不可变版本目录，回滚只允许兼容 schema；不自动回滚数据库。
- 重连不包含取消任务，新的手动任务订阅按创建主体保护。

## 设计审查记录

已由独立审查代理只读核对 Windows 进程、Compose、模型调用和数据路径。审查提出共享租约失联后的上游并发语义不明，已明确为有效租约数量上限及失联故障边界；同时固定共享数据目录与不可变发布目录解耦。其余关注项无需要新增用户输入的重要遗漏。用户随后批准实施。
