# 使用反馈与指标口径

新增数据库迁移 `20261019_0008`，部署前按项目原有迁移流程升级。默认开启 `USAGE_TRACKING_ENABLED=true`。真实使用环境设置 `USAGE_DATA_ORIGIN=real`，自动化评测环境必须设置 `USAGE_DATA_ORIGIN=evaluation`，不能让压测流量混入真实使用统计。

登录用户收到新回答后，可点击“已解决 / 部分解决 / 未解决”。每条回答保留一份最新评价，重复点击更新原记录。只有回答所属用户可以提交，管理员通过页面“使用统计”或 `GET /api/feedback/summary?days=30` 查看汇总。匿名 API 密钥不能提交用户评价。历史页面重新加载后暂不恢复评价按钮。

统计口径：

- 反馈解决率 = 标记已解决的回答数 / 有反馈的回答数。未评价不能算已解决。
- 反馈覆盖率 = 有反馈的回答数 / 已完成且关联登录用户的回答数。
- 活跃用户 = 时间窗口内交互记录中去重的登录用户数；共享账号不代表多个独立用户。
- P95 耗时仅统计完成的请求，从应用开始处理计时；客户端网络和请求进入前的排队时间不全包含。
- Token 只汇总完整返回 usage 的已观测模型调用，展示覆盖率；缺失值保留为空，不能视为零或供应商账单。

无反馈时解决率为空。评测数据永久排除在真实反馈汇总之外。建议试用者按真实任务独立评价，并记录试用日期、任务类型和未解决原因；汇报时同时给出样本数、覆盖率和统计时间，不只给百分比。

交互统计表存储会话哈希、用户关联、状态、耗时、调用用量和回答长度，不额外复制完整问题或回答。用户主动填写的备注仍可能含敏感信息，应遵守部署方的数据保留制度。

模型保护参数：`CHAT_MAX_CONCURRENT=4`、`CHAT_MAX_WAITING=16`、`CHAT_QUEUE_TIMEOUT_SECONDS=30`，仅限制单进程；多副本需要共享限流与配额控制。上游 429 会触发短暂熔断，但不能增加供应商额度。

上下文预算使用保守的 UTF-8 载荷估算并保留完整最近对话轮次，不是供应商精确 tokenizer，也不覆盖全部工具定义与输出预留。上线应依据实际模型窗口继续配置余量。
